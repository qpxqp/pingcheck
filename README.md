# Ping Checker

Пингует IP-адреса из Excel-файла и сохраняет результаты:

- в исходный файл — добавляет колонку `YYYY-MM-DD hh:mm:ss`
  с процентом успешных пакетов по каждому IP;
- в отдельный файл — отчёт `results/YYYY-MM-DD_hh-mm-ss.xlsx`
  (все метрики по каждому IP).

Поддерживает Windows и Linux. Умеет работать без прав администратора (UDP-режим).

---

## Что считает

Для каждого IP выполняет ping (`count` пакетов, по умолчанию 2).
В отчёт попадают:

| Столбец       | Пояснение                                                      |
|---------------|----------------------------------------------------------------|
| `ip`          | IP-адрес                                                       |
| `alive`       | `True`, если пришёл хотя бы один ответ                         |
| `success_pct` | процент успешных пакетов, `0..100`                             |
| `ping_count`  | сколько пакетов отправлялось (`--count`)                       |
| `avg_rtt`     | среднее время отклика, мс                                      |
| `min_rtt`     | минимальное время отклика, мс                                  |
| `max_rtt`     | максимальное время отклика, мс                                 |
| `jitter`      | вариация задержки, мс (может быть пусто при <2 ответах)        |
| `packet_loss` | доля потерянных пакетов, `0..1`                                |
| warnings | предупреждения (нормализация IP, резолв hostname, ошибки) или пусто |

### Как считается `success_pct`

```python
success_pct = round(recv / sent * 100) if sent else 0
```

- `sent` — сколько пакетов отправили (равно `--count`);
- `recv` — сколько пакетов получили обратно;
- `success_pct` — доля полученных пакетов в процентах, округлённая до целого.

Примеры:

| `--count` | получено | `success_pct` | `alive` |
|-----------|----------|---------------|---------|
| 2         | 2        | 100           | True    |
| 2         | 1        | 50            | True    |
| 2         | 0        | 0             | False   |
| 3         | 2        | 67            | True    |

Теоретически `sent` может быть 0, если библиотека не
смогла отправить ни одного пакета (например, из-за сетевой ошибки).
В этом случае `success_pct = 0`.

### Что такое packet_loss

Это доля потерянных пакетов от 0 до 1:

- 1.0 — потеряно 100% (узел недоступен);
- 0.5 — потеряно 50%;
- 0.0 — потерь нет.

## Установка

### 1. uv

Установите [uv](https://docs.astral.sh/uv/) — менеджер Python-проектов и пакетов.

Windows (PowerShell):

```bash
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Linux / macOS:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

После установки перезапустите терминал и проверьте:

```bash
uv --version
```

### 2. Git

Для клонирования репозитория нужен Git.

Windows: скачайте и установите [Git for Windows](https://git-scm.com/download/win).
Вместе с Git будет установлен **Git Bash** — терминал, в котором доступны
команды `git`, `cd`, `curl` и другие. Все команды из этого README
на Windows удобнее выполнять именно в Git Bash (PowerShell тоже
подойдёт, но синтаксис некоторых команд отличается).

Linux (Debian/Ubuntu):

```bash
sudo apt install git
```

macOS: git входит в Xcode Command Line Tools, либо:

```bash
brew install git
```

Проверка:

```bash
git --version
```

### 3. Репозиторий проекта

```bash
git clone https://github.com/qpxqp/pingcheck.git
```

```bash
cd pingcheck
```

### 4. Зависимости проекта

В каталоге проекта выполните:

```bash
uv sync --no-dev
```

Эта команда автоматически создаст виртуальное окружение и установит все зависимости проекта. Python устанавливать отдельно не нужно — `uv` загрузит подходящую версию автоматически, если её нет в системе.


## Использование

```bash
uv run pingcheck.py
```

По умолчанию:

- исходный файл с IP-адресами — `ips.xlsx` рядом со скриптом;
- столбец с IP-адресами — `ip`;
- 2 пакета на каждый адрес, таймаут 3 с;
- ICMP-режим (нужны права администратора/root);
- в исходный файл добавляет колонку `YYYY-MM-DD hh:mm:ss` с процентом успешных пакетов по каждому IP;
- отчёты — в `results/YYYY-MM-DD_hh-mm-ss.xlsx` со всеми метриками по каждому IP;
- лог — `pingcheck.log` рядом со скриптом (дописывается при каждом запуске).

### Аргументы

| Флаг                 | По умолчанию | Описание                       |
|----------------------|--------------|--------------------------------|
| `-i`, `--input-file` | `ips.xlsx`   | путь к исходному Excel-файлу   |
| `--column`           | `ip`         | имя колонки с IP-адресами      |
| `-c`, `--count`      | `2`          | количество пакетов на адрес    |
| `-t`, `--timeout`    | `3`          | таймаут одного пакета, секунды |
| `--chunk-size`       |	`50`        |	размер чанка для группового пинга (0 — без разбивки) |
| `--no-privileged`    | —            | использовать UDP вместо ICMP                         |
| `--no-report`        | —            | не сохранять отчёт в `results/`                      |
| `--no-append-source` | —            | не добавлять колонку в исходный файл                 |
| `-v`, `--verbose`    | —            | показывать в логе результат по каждому IP            |
| `--no-log-file`      | —	          |не записывать лог в файл (только в консоль)           |

### Примеры

```bash
# по умолчанию (ICMP, 2 пакета)
uv run pingcheck.py

# UDP-режим (без прав администратора для Linux/macOS)
uv run pingcheck.py --no-privileged

# свой файл и столбец с IP-адресами, 4 пакета
uv run pingcheck.py -i hosts.xlsx --column address -c 4

# только отчёт в results/, исходный файл не изменяется
uv run pingcheck.py --no-append-source

# только колонка в исходном файле, отчёт не в отдельный файл не сохраняется
uv run pingcheck.py --no-report

# сухой прогон: только ping и лог `pingcheck.log`
uv run pingcheck.py --no-report --no-append-source

# сухой прогон с отладочным выводом по каждому IP в лог
uv run pingcheck.py --no-report --no-append-source -v

# ограничить чанк до 10 адресов и отключить запись лога в файл
uv run pingcheck.py --chunk-size 10 --no-log-file
```

### Формат входного файла

Минимально — один лист со столбцом с IP-адресами (по умолчанию `ip`):

| ip          |
|-------------|
| 8.8.8.8     |
| 1.1.1.1     |
| 192.168.1.1 |

После запуска в этом же файле появится новый столбец с датой-временем
запуска и долей полученных пакетов в процентах по каждому IP.

## Права администратора

- ICMP (`--privileged`, по умолчанию) — требует прав администратора
  (Windows) или root (Linux/macOS).
- UDP-режим (--no-privileged) — на Linux/macOS позволяет работать без root.
  На Windows этот флаг игнорируется: запуск всё равно требует прав администратора.

## Логи

По умолчанию лог пишется в файл `pingcheck.log` рядом со скриптом в режиме дописывания.
Если вы не хотите, чтобы создавался файл лога, используйте флаг `--no-log-file`.
В этом случае вывод будет осуществляться только в консоль.
Формат:

```text
2026-11-03 14:05:09 [INFO] ===== Process started =====
2026-11-03 14:05:09 [INFO] В файле `.../ips.xlsx` найдено 3 IP
2026-11-03 14:05:11 [INFO] Пинг 3 адресов...
2026-11-03 14:05:12 [INFO] Успешно: 2
2026-11-03 14:05:12 [INFO] Неуспешно: 1
2026-11-03 14:05:12 [INFO] Результаты сохранены в `.../results/2026-11-03_14-05-09.xlsx`
2026-11-03 14:05:12 [INFO] ===== Process finished =====
```

С флагом `--verbose` в лог добавляется строка по каждому IP
с оригинальным адресом из исходного файла:

```text
...
2026-11-05 12:00:01 [INFO] Результаты:
2026-11-05 12:00:01 [INFO] 192.168.1.1          OK
2026-11-05 12:00:01 [INFO] 8.8.8.8              OK
2026-11-05 12:00:01 [INFO] asasa.asasas         FAIL: The name 'asasa.asasas' cannot be resolved
2026-11-05 12:00:01 [INFO] 10.0.0.1             FAIL
...
```

Файл растёт без ротации — при частом запуске следите за размером.

## Коды выхода

| Код | Когда                                                          |
|-----|----------------------------------------------------------------|
| 0   | успех                                                          |
| 1   | файл не найден / нет колонки / ошибка пинга / нет прав доступа |
| 2   | нет зависимости (openpyxl) или непредвиденная ошибка           |

## Ограничения

- Перезапись исходного файла через `pandas.to_excel` уничтожает
  форматирование, формулы, другие листы и объединённые ячейки.
  Если это важно — используйте только отчёт в `results/`, а запись
  в исходник отключите.
- `icmplib` не поставляет type stubs; для mypy добавьте
  `ignore_missing_imports = true` для `icmplib.*`
  (и `pandas-stubs` для pandas).
- На Windows запись в исходный файл упадёт, если файл открыт в Excel
  (PermissionError). Скрипт это перехватывает и пишет в лог.
